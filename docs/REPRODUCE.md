# Reproducing AquaSphere

Everything on the site and in `docs/results` is generated by the commands below from open data.
No account is needed: satellite fields come from NOAA ERDDAP and Argo profiles from Argovis.

## Quick start: run the app

```bash
git clone https://github.com/FarhanAaqil/AquaSphere.git && cd AquaSphere
pip install -e ".[dev,e2e]"            # add ,onnx for faster CPU serving
make serve                             # http://127.0.0.1:8000
```

A fresh clone has no data or weights, so the API serves untrained v1 weights and says so
(`/ready` reports `ready: false`, every response carries `+untrained`). To serve the trained
protocol v2 model either rebuild everything (below, about 3 hours on a laptop CPU) or unpack the
release assets:

```bash
# download from https://github.com/FarhanAaqil/AquaSphere/releases/tag/v1.0.0 into dist/release/:
# model weights, the 2015-2025 store, the Argo tables and SHA256SUMS
python scripts/package_release.py --verify   # after placing the archives in dist/release
tar -xzf dist/release/aquasphere-model-tier_a_v2.tar.gz
tar -xzf dist/release/aquasphere-nio-store-2015-2025.tar.gz
tar -xzf dist/release/aquasphere-argo-nio.tar.gz
make serve
```

With `checkpoints/tier_a_v2/model.pt` and `data/store/surface_nio.zarr` present the API serves the
v2 model on the real store automatically (`AQUASPHERE_STORE` overrides the store).

## Full rebuild from open data

```bash
make reproduce
```

| Step | Target | What it does | Time (laptop CPU) |
|---|---|---|---|
| 1 | `make data-store` | 0.25° daily store 2015-2025 from ERDDAP (OISST, NESDIS SLA and currents, SMAP SSS, blended winds) | 40-90 min first time; cached in `data/cache/satellite` |
| 2 | `make data-argo` | Argo 2015-2025 via Argovis, QC, PCHIP to 15 depths, data mode flag | 20-40 min first time; cached |
| 3 | `make data-collocate` | Satellite values at each profile | 2 min |
| 4 | `make data-coverage` | Coverage report | 1 min |
| 5 | `make data-patches` | 9x9 patch stacks at 4 lags, and unlabelled 2015-2022 patches | 1 min |
| 6 | `make eval` | Protocol v2: E1 leakage gap, E2 baseline ladder B0-B4, strata and power | 25 min |
| 7 | `make eval-phase4` | Physics ablation, E3-E7, and the served Tier A v2 checkpoint | 90 min |
| 8 | `make ui-data` | Copies results into `web/data`, rebuilds floats, dates and the offline precache list | 1 min |

Then:

```bash
make regression        # the served checkpoint reproduces docs/results/phase4.json
make eval-rama         # E8: RAMA moorings (downloads about 1 MB per mooring once)
make onnx              # optional: export the served network for onnxruntime
```

## The test period

`make eval-test` is the single read of the 2024-2025 test period. It logs the read to
`docs/results/test_access.log` and refuses to run once `docs/results/final_eval.json` exists, so
`make reproduce` deliberately stops before it. `make eval-test-dry` runs every step of it on 2023
instead, without unlocking anything. The hypotheses it tests were frozen beforehand
(`docs/hypotheses.yaml`, tag `hypotheses-v1-2026-10-29`); how each p-value is computed was written
down before the read (`docs/hypotheses_deviations.md`).

## Checks

```bash
make lint typecheck    # ruff, mypy
pytest tests/ --cov=aquasphere --cov-fail-under=80
pytest tests/e2e --no-cov   # browser tests incl. WCAG 2.1 AA (needs: python -m playwright install chromium)
```

`tests/unit/test_frozen_results.py` fails if any file in `docs/results` changes without
`make freeze-results`, so numbers cannot drift silently.

## Docker

```bash
docker build -t aquasphere .
docker run -p 8000:8000 aquasphere
```

The image includes the `onnx` extra. Mount `checkpoints/` and `data/store/` to serve the trained
model: `docker run -p 8000:8000 -v $PWD/checkpoints:/app/checkpoints -v $PWD/data/store:/app/data/store aquasphere`.

## Release assets

`make release` packs the weights, the demo store, the 2015-2025 store and the Argo tables into
`dist/release/` with `SHA256SUMS`. Raw data is never committed to git.
